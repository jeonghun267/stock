1. 가장 먼저 확인할 치명 결함
############################################################

A. manual_buy_block.flag 처리

현재 ExecutionAdapter.connect()는 LIVE일 때
manual_buy_block.flag가 존재하면 브로커 연결 자체를 거부한다.

이 구조는 신규 BUY만 차단하는 것이 아니라,
기존 보유 포지션의 SELL 관리까지 막을 가능성이 있다.

확인할 것:
- manual_buy_block.flag 존재 시 BUY만 차단되는가
- SELL은 항상 연결·실행 가능한가
- 연결 자체를 막으면 안 되는지
- 기존 broker_client.py 공통관문과 중복되는지

수정 방향:
- 브로커 연결은 유지
- BUY에서만 manual_buy_block.flag 검사
- SELL은 차단 플래그와 무관하게 허용
- 단, 사용자 승인 전 실제 수정하지 말고 먼저 보고

B. 실체결 계약

현재 신규 엔진은 send_order_real() 응답 상태만 사용한다.
다음이 구현되어 있는지 확인하라.

- 접수 OK와 실제 체결 분리
- 주문번호 확보
- fills_YYYYMMDD.csv 체결확인
- 부분체결
- 미체결 잔량 취소
- 취소완료 확인
- 매수 체결 전 HOLD 진입 방지
- 매도 체결 전 CLOSED 처리 방지
- 실체결 평균가로 entry_price/exit_price 갱신
- 다른 엔진 주문과 체결 귀속 혼동 방지

현재 빠져 있으면 LIVE 금지 사유로 명시한다.

C. 슬롯·자금 계약

확인할 것:
- shared_slots.py와 연결되어 있는가
- 기존 캡틴·골짜기와 자금/슬롯 충돌이 없는가
- 최대 포지션 1개가 엔진 내부만의 제한인지 계좌 전체 제한인지
- 주문 실패·미체결 시 슬롯 반환
- 부분체결 시 실제 수량만 슬롯/장부 반영
- 재시작 후 계좌 실제 보유와 captain2_state.json 동기화
- 기존 rt_open_positions.json/reconcile과 연결 필요 여부

D. 후보 유니버스 계약

현재 엔진은 micro_rank_board의 MONEY_START를 직접 사용한다.

확인할 것:
- 시장 전체 대상인지, 실시간 등록 종목만 대상인지
- 스냅샷과 board 종목코드가 정확히 일치하는지
- snapshot ts와 board ts의 신선도 검사가 각각 있는지
- MONEY_START 단독으로 진입하는 구조가 사용자 최종 의도인지
- 기존 +3% 캡틴은 독립 유지되는지
- 기존 캡틴과 CAPTAIN2가 동시에 같은 종목을 주문할 위험

사용자 최종 방향:
CAPTAIN2는 위치와 무관하게 강한 돈 유입을 잡는 독립 엔진을 목표로 한다.
그러나 검증 전에는 SHADOW이며 기존 캡틴을 대체하지 않는다.

3. RESET 계산 점검
############################################################

의도:
거래대금 폭증 시점을 감지한 후 실제 저점을 탐색하고,
저점 시점의 누적거래량·체결강도를 기준값 0으로 소급 리셋한다.

확인할 것:
- FLOW 감지 즉시 RESET하지 않는가
- LOW_SEARCH 중 신저점마다 가격/cum_vol/che_str/호가가 같은 시점으로 갱신되는가
- 저점 확정 후 candidate_low 시점으로 소급하는가
- 저점부터 확정 시점까지 buffer가 보존되는가
- 계속 하락 시 FAILED 처리
- 가짜 반등 후 저점 재이탈 처리
- 같은 MONEY_START 파동 중 중복 RESET 방지
- money_start_raw OFF 후 ON일 때만 재무장되는가
- 60초 같은 고정창 때문에 동일 파동이 분할되는가

############################################################
4. 매수·매도 체결량 추정식 점검
############################################################

사용자 의도:
장 시작부터의 전체값을 직접 판단하지 않는다.
저점 RESET 시점부터 현재까지의 구간만 차분한다.

현재 방식:
cum_vol과 누적 che_str로 시점별 누적 매수/매도를 역산한 뒤
RESET 시점 값을 빼서 구간 추정치를 만든다.

반드시 명시:
- 실제 틱별 매수체결/매도체결 원시합이 아니라 추정치
- 음수 추정치, cum_vol 역행, che_str 비정상 방어
- buy_exec_vol + sell_exec_vol이 delta_cum_vol과 일치하는지
- 0 나눗셈 방어
- RESET 직후 표본 부족 시 BUY 금지
- 초당 마지막 스냅샷만으로 중간 틱을 잃는 한계

사용자 의도와 다르게 장중 전체 평균을 다시 사용하지 마라.

- 프로세스 재시작 시 상태 복원
