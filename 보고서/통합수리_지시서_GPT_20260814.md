## 1-1. 사고 연쇄

오늘 하루 사고는 **전부 하나의 원인에서 나왔다.**

| 시간 | 피해 | 원인 |
|---|---|---|
| 새벽~08:33 | 일봉 3일치 결손(8/12·8/13) | 공유 대기루프 |
| 09:00~14:41 | **1분봉 통째 결손** — 오늘 1분봉은 14:09부터만 존재 | 〃 |

| 하루 종일 | TIMEOUT 166건 · BROKER-DEAD 92건 · 회로차단 86건 | 〃 |

## 1-2. 근본 원인 — 공유 `tr_loop`

브로커의 모든 TR이 **하나의 `QEventLoop`를 공유**한다.

```
A가 TR 요청 → 대기 시작
B의 응답이 먼저 도착 → 공유 루프가 깨어남 → A도 같이 깨어난다
A는 자기 버퍼를 본다 → 비어 있다 → "TIMEOUT" 으로 판정
   (실제로는 브로커가 응답을 보냈다. A가 남의 응답에 깨어났을 뿐이다)
```

### 🔑 진단할 때 절대 잊지 말 것

**브로커 로그로는 이 결함이 보이지 않는다.**
브로커는 "응답 보냄"으로 기록하고, 클라이언트만 TIMEOUT을 기록한다.
로그 대조로 "브로커는 정상"이라는 결론에 도달하면 **그 결론은 틀렸다.**

판단은 반드시 **결과물**로 하라:
- `eod_daily_bars.csv` 의 mtime이 갱신됐는가
- `prices_1m.csv` 에 09시대 봉이 쌓였는가

## 1-3. 2차 피해 — 검증 자체가 불가능해졌다

당일 일봉 행이 **전부 가짜**가 됐다.

```
검사: 오늘(20260814) 행 1630개 중 시가=고가=저가=종가 이면서 거래량 0
결과: 1630 / 1630   (전부)

샘플: 000250 삼천당제약  O 189800  H 189800  L 189800  C 189800  V 0
대조: 어제(20260813) 1630행 중 시가대비 저가 -4% 이하 = 431 종목 (정상)
```

아침 수집이 장 시작 전이라 값이 없는 당일 행을 만들어 넣었고,
16:05 수집이 실패해 **하루 종일 안 덮였다.**

그 결과 오늘은 **"S03이 급락을 다 잡았나"를 검증할 자료가 아예 없었다**
(일봉=가짜 · 1분봉 14:09부터 · 3분봉 14:30~15:15 72종목뿐 · 고저폭 그림자 09:00 1회).

# A항. 좀비 감지 확대 — **지금 바로 착수**

## A-1. 확정된 사실 — 감지기는 있었는데 눈을 감고 있었다

`RUN\watchdog_broker_gateway_v1.ps1` (8/13 11:16 작성) 의 설정:

```powershell
$JAM_WINDOW_SEC       = 300           # 최근 5분을 본다
$JAM_MAX_OK           = 1             # 성공이 1건 이하이고
$JAM_MIN_TIMEOUTS     = 12            # TIMEOUT 이 12건 이상이면 = 좀비
$JAM_CHECK_START      = "08:40:00"    # ← 여기부터
$JAM_CHECK_END        = "15:30:00"    # ← 여기까지만 검사한다
$JAM_KILL_MIN_GAP_SEC = 600           # 10분에 한 번만 강제종료
```

오늘 사고를 이 잣대에 대보면:

```
사고 시간   16:05 ~ 18:34  (2시간 29분)
그 구간     TIMEOUT 98건 / 성공 0건 / 저장 0건
판정        성공 0 ≤ 1  그리고  TIMEOUT 98 ≥ 12   → 좀비 조건 100% 충족
실제 동작   아무 일도 안 일어남
이유        16:05 은 15:30 이후 = 검사창 밖
```

**논리는 완벽했다. 시간창만 좁았다.**
8/13 당시 사고가 이틀 연속 08:43분대라 장중만 보게 했는데, **그 전제가 오늘 깨졌다.**

## A-2. 수리 내용 (이것만)

### ① 검사창을 넓힌다

```
$JAM_CHECK_START : 08:40  →  08:35
$JAM_CHECK_END   : 15:30  →  22:45
```

**근거**: `RUN\broker_night_stop.ps1` 주석에 명시 —
*"22:45~익일 08:35는 브로커를 쓰는 태스크가 없음(전수조사)"*.
즉 **브로커가 살아 있는 모든 시간이 감시 대상이어야 한다.**

### ② 장 마감 후에는 강제종료 간격을 늘린다

```
장중(15:30 이전)   $JAM_KILL_MIN_GAP_SEC = 600  (10분)  ← 그대로
장 마감 후          1800 (30분) 으로
```

**이유**: 저녁 일봉 수집은 한 종목당 최대 30초가 정상 범위다.
10분 간격으로 되살리면 **수집을 반복해서 죽이는 사고**가 난다.
장중은 매도가 걸려 있으니 10분을 유지한다.

### ③ ⚠️ 수집기 보호 — 여기가 이 항목의 핵심

강제종료 대상은 **브로커**지만, 브로커를 죽이면 **수집기도 같이 무력화**된다.
따라서 강제종료 직전에 다음을 확인하고 해당하면 **건너뛰어라**:

```
LOG\collect_eod.heartbeat 가 살아 있고 진행 중이면 → 강제종료 금지
```

같은 방어가 **이미 `broker_night_stop.ps1` 0단계에 있다. 그 코드를 그대로 베껴 써라.**
새 방식을 만들지 마라.

🔑 **단, 하트비트만 보면 오늘 같은 좀비를 또 놓친다.**
오늘 좀비는 **하트비트가 멀쩡히 뛰면서 아무것도 못 하고 있었다.**
그러므로 판정은 **하트비트 + 진행률**로 하라:

```
heartbeat 의 idx 값이 지난 10분간 그대로 → 살아 있지만 진행 없음 = 좀비 (죽여도 된다)
heartbeat 의 idx 값이 늘고 있음          → 정상 진행 = 죽이지 마라
```

`LOG\collect_eod.heartbeat` 실제 내용:

```json
{"ts": "2026-08-14T18:51:48", "pid": 9052, "idx": 380, "total": 1821,
 "pct": 20.9, "eta_min": 57.9, "sleep": 0.379, "version": "..."}
```

**`idx` 가 판정의 핵심이다.** 멈추면 좀비, 늘면 정상.

## A-3. 검증 (3종 전부 통과해야 완료)

1. **좀비 구간** — 오늘 `LOG\broker_journal.log` 의 **16:05~18:34** 구간을 감지 함수에 넣어
   판정이 **참**인지 확인. (오늘이 완벽한 시험 자료다)
2. **정상 구간** — 같은 감지기에 **18:36 이후** 구간을 넣어 판정이 **거짓**인지 확인.
   🚨 **이걸 빼먹지 마라.** 막는 것만 확인하고 통과하는 것을 안 보면 반쪽 검증이다.
   (오늘 "성공 1건"으로 해소를 선언한 것과 같은 실수를 반복하지 마라.)
3. **수집기 보호** — `idx` 가 증가 중인 상황에서 **강제종료가 안 걸리는지** 확인.

하나라도 실패하면 **원복**.

## A-4. 제약

- **`.ps1` 은 ASCII 전용.** 한글 주석 금지 — 실사고 전례 있음.
- 백업: `watchdog_broker_gateway_v1_20260814_before_night_window.ps1`
- **문턱값(`JAM_MAX_OK`, `JAM_MIN_TIMEOUTS`)은 건드리지 마라.** 8/13에 실자료로 뽑은 값이다.
  이번 변경은 **시간창과 안전장치뿐**이다.
- 지금은 **파일 편집 + 오프라인 재생까지만.** 워치독 프로세스 재기동은 수집 완료 후.

## A-5. 이 수리의 한계 (반드시 인지할 것)

**막아준다**: 좀비가 생겼을 때 5분 안에 자동 복구. 오늘처럼 2시간 29분을 버리지 않는다.

# C항. 빈 껍데기 일봉 행 — **수집 완료 후 판단**

1-3절이 배경이다.

## 먼저 확인할 것

오늘 수집이 끝나면 당일 행이 진짜 값으로 덮이는지 본다:

```
① eod_daily_bars.csv mtime 이 19:50 이후로 갱신됐는가
② 당일 행의 고가 ≠ 저가 인가        ← 빈 껍데기가 덮였나
③ 어제처럼 급락 종목이 수백 개 잡히는가
```

**셋 다 통과하면 C항은 오늘 자연 해소된 것이다.** 그래도 구조 수리는 필요하다 —
수집이 실패하는 날마다 같은 일이 반복되기 때문이다.

## 수리 방향 (둘 중 **하나만**)

- **A안 (권장)** — 일봉을 읽는 쪽이 **당일 행을 제외**한다.
  지표는 원래 "전일까지 확정 일봉"으로 계산하는 게 맞다.
- **B안** — 수집 쪽이 **빈 껍데기 행을 아예 안 만든다**(값이 없으면 행을 쓰지 않는다).

⚠️ 둘 다 하지 마라. 어느 쪽이 효과를 냈는지 추적 불가해진다.
