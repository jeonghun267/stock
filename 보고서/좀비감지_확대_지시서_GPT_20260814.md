## 2. 수리 지시 (이것만. 다른 건 건드리지 마라)

### 2-1. 검사창을 넓힌다

```
$JAM_CHECK_START : 08:40  →  08:35   (워치독 기동 시각과 맞춘다)
$JAM_CHECK_END   : 15:30  →  22:45   (밤 정지 시각과 맞춘다)
```

**근거**: 브로커를 쓰는 태스크는 08:35~22:45 사이에 존재한다.
(`RUN\broker_night_stop.ps1` 주석: "22:45~익일 08:35는 브로커를 쓰는 태스크가 없음(전수조사)")
즉 **브로커가 살아 있는 모든 시간이 감시 대상이어야 한다.**

### 2-2. 장 마감 후에는 강제종료 간격을 늘린다

```
$JAM_KILL_MIN_GAP_SEC = 600 (10분)   ← 장중엔 이대로
장 마감 후(15:30 이후)              → 1800 (30분) 으로
```

**이유**: 저녁 일봉 수집은 한 종목당 최대 30초가 정상 범위다.
10분 간격으로 되살리면 **수집을 반복해서 죽이는 사고**가 날 수 있다.
장중은 매도가 걸려 있으니 10분을 유지하고, 저녁은 여유를 준다.

### 2-3. ⚠️ 반드시 지켜야 할 안전장치 — 수집기를 죽이지 마라

강제종료 대상은 **브로커**다. 그런데 브로커를 죽이면 **수집기도 같이 무력화**된다.
따라서 강제종료 직전에 다음을 확인하고, 해당하면 **건너뛰어라**:

```
LOG\collect_eod.heartbeat 의 mtime 이 10분 이내 = EOD 수집기가 살아 진행 중
  → 이때는 강제종료 금지 (진행 중인 백필을 죽이는 사고 방지)
```

이 방어는 **이미 `broker_night_stop.ps1` 에 같은 형태로 들어 있다**(0단계).
그 코드를 그대로 베껴 쓰면 된다. 새 방식을 만들지 마라.

🔑 **단, 오늘 사고는 "하트비트는 뛰는데 아무것도 못 하는" 상태였다.**
그러므로 하트비트만 보면 오늘 같은 좀비를 또 놓친다. 판정은 **하트비트 + 진행률**로 하라:

```
heartbeat 의 idx 값이 지난 10분간 그대로면  = 살아 있지만 진행이 없다 = 좀비
heartbeat 의 idx 값이 늘고 있으면          = 정상 진행 = 죽이지 마라
```

`LOG\collect_eod.heartbeat` 실제 내용(오늘 18:40):

```json
{"ts": "2026-08-14T18:40:05", "pid": 9052, "idx": 80, "total": 1821,
 "pct": 4.4, "eta_min": 77.5, "sleep": 0.379, "version": "..."}
```

**`idx` 가 이 판정의 핵심이다.** 이 값이 멈추면 좀비, 늘면 정상.

## 3. 검증 방법 (이 순서로, 증거를 남겨라)

1. **오프라인 재생** — 오늘 `LOG\broker_journal.log` 의 **16:05~18:34 구간**을 감지 함수에 넣어
   "좀비 판정 = 참" 이 나오는지 확인하라. (오늘이 완벽한 시험 자료다)
2. **거짓 경보 검사** — 같은 감지기에 **18:36 이후 정상 구간**을 넣어
   "좀비 판정 = 거짓" 이 나오는지 확인하라. **이쪽을 빼먹지 마라** —
   막는 것만 확인하고 통과하는 것을 안 보면 반쪽 검증이다.
3. **수집기 보호 검사** — 하트비트 `idx` 가 증가 중인 상황을 넣어
   **강제종료가 안 걸리는지** 확인하라.
4. 세 개 전부 통과해야 배선 완료다. 하나라도 실패하면 원복.
