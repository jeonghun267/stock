# 1. 🔴 일봉 수집이 50분째 저장 0건 + 화면 누수 의심

## 관찰 (실측, 16:55 기준)

```
data\eod_daily_bars.csv   mtime = 08-17 19:16:55   ← 어제 것. 오늘 저장 0건
eod_daily_bars.csv 의 20260818 행수 = 0
SAFEPLUS_COLLECT_EOD_BARS  State=Running  Last=08-18 16:05:05  Result=267009(실행 중)
→ 16:05 시작 후 50분 경과, 아직 저장 없음
```

**브로커 TR 상태 (최근 5분)**
```
status=OK       35건
status=TIMEOUT  55건    ← 61% 타임아웃
```

`[기억]` 8/14 좀비 지문은 **"TIMEOUT 100% + OK 0건"** 이었다.
**지금은 OK 가 있으므로 완전 좀비는 아니다. 느리게 진행 중이다.**

## 🔑 진짜 의심 지점 — 화면 2211 지연 응답 무한 반복

```
16:54:45  OnReceiveTrData rqname=B002EF2D2341340 tr_code=opt10001 screen_no=2211
16:54:45  WARNING 현재 요청 불일치 - 지연 응답 무시  got=(B002EF2D2341340,opt10001,2211) expected=
16:54:55  (동일 반복)
16:55:05  (동일 반복)

```

- **같은 응답이 정확히 10초 간격으로 계속 되돌아온다.**
- **`expected=` 가 비어 있다** — 브로커는 아무 요청도 기다리지 않는데 응답만 들어온다.
- `[추정]` **화면번호 2211 이 해제되지 않고 남아 데이터를 계속 밀어내는 것**으로 보인다.
  이것이 TR 슬롯을 잡아먹어 TIMEOUT 61% 를 만들고 있을 가능성.
- `[기억]` 8/13 "화면 0796 좀비"와 같은 계열(화면 누수)이다.

## 조사·조치할 것

### 1-A. 수집 완료 여부를 먼저 확인하라 (판단의 전제)

- `eod_daily_bars.csv` 에 `20260818` 행이 들어왔는가?
- 안 들어왔으면 **몇 종목까지 처리했는지** 진행 상태를 찾아라(중간 저장 파일·로그).
- **정상일의 수집 소요 시간과 비교하라** — 8/11·8/12·8/13 은 16:05 시작해서 몇 분에 끝났는가?
  이 대조 없이 "느리다/정상이다"를 판정하지 마라.

### 1-B. 화면 2211 누수 규명

- `screen_no=2211` 을 등록한 주체가 무엇인가? (`rqname=B002EF2D2341340`, `tr_code=opt10001`)
  - `B` 접두어가 무엇을 뜻하는지 코드에서 확인하라.
- 이 화면이 **왜 해제되지 않는가?** 해제 경로(`DisconnectRealData`·`SetRealRemove`)가 호출되는가?
- `expected=` 가 빈 상태로 응답을 받는 것이 **정상 동작인지 버그인지** 판정하라.
- 이 반복이 **TR 슬롯/처리량을 실제로 잠식하는지** 근거를 대라.
  (잠식하지 않는다면 로그만 시끄러운 것이고 우선순위가 내려간다)

### 1-C. 오늘 밤 백스톱이 작동하는지 확인

`[기억]` 22:45 야간정지, 새벽 `FRESHNESS_GUARD` 02:00·05:00·07:30 이 보험이다.

- 수집이 실패로 끝날 경우 **이 보험들이 오늘 일봉을 채우는가?**
- 내일 08:40 고저폭판이 `source_stale` 이 되지 않으려면 **몇 시까지** 일봉이 들어와야 하는가?

  S01 매수창 소실, S06 대상 0. 이 사슬을 막는 것이 목적이다.

### 1-D. 하지 말 것

# 2. 🟡 레짐 면제(REGIME_STOP_EXEMPT) 사후 근거 점검

## 확인된 사실 — 네 진단이 맞았다

Claude 가 처음에 "오늘 코스닥은 상승했다"고 한 것은 **09:40 까지만 본 불완전한 관찰**이었다.
전체 흐름 실측:

```
09:02 시작   860.29
10:14 최고   871.99
15:08 최저   828.05    ← 시작 대비 -3.75%
15:29 마지막 834.77    ← 시작 대비 -2.97%
고점 대비 최저 -5.04%
```

**주문 시각(15:23~15:25)은 -3% 구간이었다. 레짐스탑 발동이 맞다.**
`REGIME_STOP_EXEMPT` 진단은 정확했고, 친구님이 승인해 이미 적용됐다.

## 그래서 지금 물을 것 — "면제가 유리한가"

`[기억]` 승인 근거였던 백테는 **상한가 종가매수 → 익일 시가 매도 = 평균 +5.976%, 승률 76.5%** 다.
그러나 **그 백테가 폭락일을 따로 떼어 보았는지는 확인된 바 없다.**

레짐스탑은 원래 **폭락일에 신규 진입을 막으려고** 만든 안전장치다.
그것을 종가매수만 면제했다면, **"폭락일의 상한가"가 평시와 같은 성과를 내는지** 반드시 확인해야 한다.

### 2-A. 레짐 조건부 백테 (핵심)

기존 백테(`RUN\eodgap_limitup_score_backtest_v1.py` 계열)를 **당일 지수 등락으로 나누어** 재집계하라.

```
상한가 종가매수 → 익일 시가 매도, 비용 0.38%p 차감
  당일 코스닥 등락 구간별:
    +1% 이상      N건  평균 __%  승률 __%
    -1% ~ +1%     N건  평균 __%  승률 __%
    -3% ~ -1%     N건  평균 __%  승률 __%
    -3% 이하(폭락) N건  평균 __%  승률 __%   ← 이번 면제가 새로 여는 구간
```

- **폭락일 구간이 다른 구간과 비슷하거나 낫다** → 면제는 타당하다
- **폭락일만 확연히 나쁘다** → 면제가 손실을 키운다. **친구님께 재검토를 건의하라**
- 표본이 10건 미만인 구간은 **"판정 불가"** 로 명시하라

### 2-B. 부작용 범위 확인

- `REGIME_STOP_EXEMPT=EODGAP_LOWBUY_,EODGAP_` 로 **정확히 어느 경로가 열렸는가?**
  접두어 매칭이라면 의도치 않게 함께 열린 경로는 없는가?
- S01·S02·S03 등 **다른 전략은 여전히 차단되는지** 코드로 확인하라
  (네 보고에 "S02 는 -3.52% 에서 계속 차단됨"이 있었다. 그 근거를 제시하라)

### 2-C. 내일이 첫 실전이다

- 면제는 **다음 08:35 기동부터 적용**된다. 내일 15:18 이 면제 후 첫 시험이다.
- **내일 코스닥이 또 -3% 이하로 가면** 면제 덕에 주문이 나간다. 그 결과가 검증 자료다.
- 결과를 반드시 기록으로 남길 설계를 제시하라(어느 로그에 무엇이 남는가).
