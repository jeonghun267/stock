### A-6-0. 먼저 알아야 할 순환 문제 — 이것 때문에 순서가 갈린다

**recorder를 만들어도 S06이 뜨지 않으면 입력이 한 건도 안 쌓인다.**

그래서 **3단계로 나눈다.** 이 순서를 지키지 않으면 영구 교착이다.

| 단계 | 시점 | 할 일 | 실전 거동 |
|---|---|---|---|
| **1단계** | 오늘 밤 | recorder·재생기 제작 + recorder 배선 + 복구 런처 크래시 방지 + **CAS 1회** | **불변** (현재 실전값 유지) |

| **3단계** | 내일 마감 후 | 저장 입력으로 1회 재생 → **PASS일 때만** 신값 통일 + CAS 재갱신 | PASS 시에만 변경 |

⚠️ 1단계 CAS를 빼면 내일도 S06이 안 떠서 2단계가 통째로 날아간다.
⚠️ 1단계에서는 **문턱을 절대 바꾸지 않는다.** 신값 통일은 3단계에서만.

### A-6-1. 1단계 — 오늘 밤 (실전 거동 불변)

**① exact-input recorder 제작**

## B. GPT가 바로 고칠 것 — 판정을 바꾸지 않는 방어 결함 5건

전부 "매매 판정은 그대로, 죽지 않게만" 고치는 작업이다. 문턱·조건은 손대지 말 것.

### B-1. 【치명】 S01 감사기록의 해시 계산이 try 밖 — 실전 매수 엔진이 죽는다

`RUN\strategy_01_signal_contract_v2.py:121-141`

```python
    record = {
        ...
        "production_files": {
            str(path): hashlib.sha256(path.read_bytes()).hexdigest()   # ← try 밖
            for path in files
        },
        ...
    }
    path = OPEN_PRIORITY_AUDIT_ROOT / f"{now:%Y%m%d}.jsonl"
    try:                                                                # ← 여기서야 시작
```

파일 6개 중 하나라도 읽기에 실패하면 `OSError`가 아래 `except OSError: pass`를 **비껴가서** 위로 튄다.
이 함수는 실전 매수 엔진이 1초마다 부르는데 호출 사슬(`select_fresh_signals` → `_try_entries`
→ `tick` → `run`)에 예외 격리가 하나도 없다.

죽는 위치가 특히 나쁘다 — `tick()`이 매도·청산 판정을 끝내고 **`self._save()`에 도달하기 직전**에
터진다. 보유 포지션이 저장되지 않은 채 고아가 된다.

이 환경은 "남이 json을 읽고만 있어도 접근이 거부되는" 실사고 전력이 있다(8/11). 파일 잠금은
가정이 아니라 실제로 일어나는 일이다. 어제까지 4파일이던 것이 오늘 6파일로 늘어 노출도 커졌다.

**할 일**: `record` 생성 전체를 `try` 안으로 넣고, `except` 범위를 최소 `(OSError, ValueError)`로.
기록 실패가 매매를 막아서는 안 되므로 실패 시 조용히 넘어가되 로그 1줄은 남길 것.
`OPEN_PRIORITY_CAPTURE = True`가 상수로 박혀 있어 끄는 스위치가 없다 — env 스위치도 함께 달 것.

### B-2. 【치명】 S03 그림자 기록이 예외 격리 없이 실전 selector 안에 있다

`RUN\strategy_03_rotation_engine_v1.py:514-516` (호출은 553행)

```python
        reset_steps=int(number(
            row.get("dip_low_reset_steps") or row.get("reset_steps")
        )),
```

`int(NaN)`은 `ValueError`를 던진다. 이 함수는 주문 판정에 아무 영향 없는 **기록 전용**인데
`try`가 없고, 553행에서 **레인 밴드 검사보다 먼저** 모든 행에 대해 호출된다.

같은 파일의 다른 기록 경로는 전부 격리돼 있다(`_drop`, CONTRACT_FILTERED 블록, `_audit_early_rows`).
**이 신규 경로만 빠졌다.** 상위 엔진의 `run()` 루프에 try가 없어 프로세스 종료로 직행하고,
보유 포지션 매도 루프까지 함께 죽는다.

**할 일**: `_record_bottom_confirm_shadow()` 호출부를 같은 파일의 기존 관례대로 감쌀 것.

### B-3. 【높음】 실주문 경로에 금지된 NaN 우회 형태

`RUN\strategy_01_open_surge_signal_v2.py:1236`
