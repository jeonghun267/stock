## 4. 조사할 것

### 조사 1 ★최우선. `status=ERROR` 의 실제 사유를 찾아라

- `eod_gap_live.log` 의 응답이 **`'status':` 에서 잘려 있다.** 왜 잘리는지 확인하고,
  가능하면 **잘리지 않은 전문**을 다른 경로에서 찾아라(IPC 응답 파일·stdout 로그 등).
- ⚠️ IPC 응답 파일은 **300초 후 청소**된다(`responses 청소: N개 파일 제거 (>300s)`).
  오늘 것은 이미 사라졌을 수 있다. **그렇다면 "다음 발생 시 보존하는 방법"을 제시하라.**
- `broker_gateway_v1.py` 에서 **`SENDORDER_REAL` 처리 경로의 모든 ERROR 반환 지점**을 전수로 뽑고,
  각각이 로그를 남기는지 아닌지 표로 정리하라.
  **로그를 안 남기는 반환 지점이 곧 범인 후보다.**

### 조사 2. 성공한 주문과의 차이를 대조하라

- 오늘 성공한 매수(예: S02 현대무벡스 09:42:01, S03 하이젠알앤엠 09:13:45)의
  **IPC 요청 필드 전체**와 EOD_GAP 의 요청 필드를 나란히 비교하라.
- 다른 필드: `order_type` / `hoga_gb` / `price` / `qty` / `screen_no` / 인증·서명 관련 필드 / TTL
- `[기억]` 이 시스템은 **주문에 서명이 필요하고 무인증은 PING·TR 조회만 허용**된다.
  **EOD_GAP 이 서명을 붙이는지, 붙인다면 키가 유효한지 확인하라.** ← 유력 후보

### 조사 3. 브로커 상태·시각 요인

- 15:23~15:25 에 브로커가 **주문을 받을 수 있는 상태**였는지(`BrokerState`).
- 장 마감(15:20~15:30 동시호가) 구간에 주문을 막는 로직이 브로커나 클라이언트에 있는지.
- ⚠️ `[TIME-GATE] 15:00~15:25` 는 EOD_GAP **자체 시간창**이며 별개다. 혼동하지 마라.

### 조사 4. 과거 실패와 같은 증상인가

- 7/28 이후 EOD_GAP 왕복 0건이다. 그 사이 실패 로그를 뽑아
  **오늘과 같은 `status=ERROR` 인지, 다른 사유(NO_TRADE·점수미달 등)인지** 분류하라.
- 8/14 는 `[LOCKED-FIRST]` 가 발동조차 못 했고(점수 문턱), **오늘은 발동 후 주문에서 막혔다.**
  **단계가 다르다.** 이 구분을 명확히 하라.
