# 2026-07-25 운영 Captain2를 건드리지 않고 공통 주문·상태 기반을 분리하는 방법

## 접근법
1. `memory.md`와 OFF 플래그를 확인해 기존 운영 중단 상태와 보존 범위를 고정한다.
2. `shared_slots.py`, Captain2 주문 상태, broker 멱등성 구현에서 재사용할 계약만 추출한다.
3. 운영 모듈을 import하지 않는 별도 공통 모듈에 시간·입력·안전관문·주문상태·비용·직렬화만 구현한다.
4. 상태 저장 경로와 OFF 플래그 경로를 주입받게 하고 단위테스트에서는 임시 디렉터리만 사용한다.
5. mock/dry-run 테스트와 `py_compile`을 실행한 뒤 보호 파일 SHA-256을 기준선과 다시 비교한다.

## 하지 않은 것 + 이유
- 기존 Captain2·broker·shared_slots를 수정하거나 새 모듈에서 import하지 않음. 이유: 운영 동작과 저장 형식을 바꾸지 않고 공통 계약만 독립 검증해야 했기 때문이다.
- 상승보유·매도·시간청산·매수전략 판단을 구현하지 않음. 이유: 재구축 순서상 이번 단계는 전략과 무관한 기반만 대상으로 했기 때문이다.
- 비용률 기본값을 넣지 않음. 이유: 임의 비용값이 순손익을 왜곡하므로 호출자가 모든 비용을 명시적으로 주입해야 하기 때문이다.

## 재사용 규칙
운영 매매엔진에서 공통 기반을 분리할 때는 운영 모듈을 직접 가져오지 말고 계약과 상태전이만 복제한 뒤 임시경로 mock 테스트와 보호 파일 해시로 격리성을 증명하라.
