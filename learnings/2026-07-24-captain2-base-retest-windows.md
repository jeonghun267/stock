# 2026-07-24 횡보돌파 BASE에 RAID의 5초/6초 창을 재사용하면 검증된 리테스트를 전부 놓친다

## 접근법
1. 기존 `base_breakout_shadow_v1.py`와 골짜기 실전 경로를 읽어 30개 완성 1분봉·응집폭 3%·양봉 상단돌파·거래량 6배·10분 리테스트라는 검증 조건을 확정했다.
2. `base_breakout_shadow.csv`를 집계해 거래량 5배는 12건 합계 +0.03%p로 비용 전 본전이고, 6배 이상은 7건 중 5승·합계 +3.64%p임을 확인했다.
3. BASE 리테스트 뒤 캡틴2의 기존 RAID 저점 5초·매수 6초 창을 그대로 재생해 7월 23일 6배 이상 4건이 모두 미진입임을 확인했다.
4. 5.4GB 전체시장 1초 캡처에서 네 종목의 리테스트 이후 실제 저점과 매수우위 복귀 시간을 다시 계산했다.
5. 실제 저점은 0.1~66.9초, 저점 뒤 매수관문 통과는 최대 57초였으므로 BASE만 저점탐색 90초·매수확인 60초로 분리했다.
6. RESET 뒤 더 낮은 가격이 나오면 기존 RESET을 폐기하고 최초 90초 상한 안에서 저점을 다시 찾도록 계단하락 방어를 추가했다.
7. 같은 4건을 30분 재생해 전부 매수관문을 통과하고 진입 후 30분 MFE가 +0.13~+2.00%, MAE가 0~-1.02%인지 확인했다.

## 하지 않은 것 + 이유
- 기존 RAID·PULL 시간창은 바꾸지 않음. 이유: 문제는 BASE 리테스트의 시간축 차이였고 다른 레인의 검증값을 바꾸면 원인 추적이 깨진다.
- 돌파선 접촉 즉시 매수는 하지 않음. 이유: 더 낮은 저점과 매도우위가 남아 있을 수 있어 사용자의 “매도자가 많을 때 사지 않는다” 원칙을 위반한다.
- 그림자 5배 조건을 실전 BASE에 쓰지 않음. 이유: 현재 12건 성과가 비용 전 +0.03%p로 거래비용을 감당하지 못한다.
- 실행 중인 캡틴2 프로세스는 재기동하지 않음. 이유: 소스 검증·반영 범위만 승인됐고 장중 프로세스 상태를 바꾸는 별도 권한은 없었다.

서로 다른 패턴을 한 엔진에 추가할 때는 공통 매수관문은 재사용하되 패턴의 시간창은 실제 이벤트 지연분포로 따로 검증하라.
