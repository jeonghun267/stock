# 2026-07-27 캡틴2 은퇴 과정에서 중계까지 꺼졌고 기존 중계는 새전략 상태를 표시할 수 없었다

## 접근법
1. 예약작업 상태·마지막 실행시각·바탕화면 출력 갱신시각을 대조해 중계가 Disabled임을 확인했다.
2. 설치 스크립트의 은퇴 작업 목록을 추적해 캡틴2 본체와 중계가 함께 비활성화된 원인을 확인했다.
3. 기존 중계 입력을 조사해 전 엔진 체결은 읽지만 엔진 상태는 폐기된 `captain2_state.json`에 의존함을 확인했다.
4. 새전략 01~04 회전 상태·신호·이벤트와 공용 슬롯·당일 체결을 읽는 독립 주문0 중계를 만들었다.
5. 임시 폴더 테스트와 실제 바탕화면 생성으로 백지 방지·개장 전 표시·네 전략 상태·호환 HTML을 검증했다.
6. 기존 1분 예약 CMD만 새 중계로 교체하고 작업을 활성화한 뒤 즉시실행 결과 0을 확인했다.

## 하지 않은 것 + 이유
- 기존 캡틴2 중계만 그대로 다시 켜지 않음. 이유: 폐기된 상태파일을 정상 엔진처럼 표시해 사용자에게 잘못된 상태를 보여주기 때문이다.
- 브로커·TR·주문 경로를 중계에 연결하지 않음. 이유: 중계는 관찰 전용이어야 하며 거래 엔진의 장애면적을 넓히면 안 된다.
- 기존 `캡틴2_중계.html`을 삭제하지 않음. 이유: 사용자가 열어둔 기존 바로가기와 브라우저 자동 새로고침을 유지하기 위해 새 화면의 호환 사본으로 사용했다.

## 재사용 규칙
실행 엔진을 은퇴할 때 관찰 도구도 함께 꺼졌다면 단순 재활성화하지 말고 새 진실 소스에 다시 연결한 뒤 켜라.
