## 가장 값진 교훈 — 로그 잠금은 이중 사각지대다

S03 엔진이 안 뜬 진짜 이유:

```
좀비(PID 19324, 관리자권한)가 sched_STRATEGY03_LIVE.log 를 독점 잠금
  → cmd 의 ">> log 2>&1" 리다이렉션 실패
    → python 이 아예 실행되지 않음
      → 태스크는 result=0x00000000 (성공!)   ← 사각지대 1
        → 로그에도 아무 흔적 없음             ← 사각지대 2
```

**"성공"으로 보고되면서 실제로는 아무 일도 안 한다.**
로그를 못 여니 로그에 실패 기록이 남을 수가 없다 — 구조적으로 증거가 안 남는다.

### 판별법 (다음에 3초 만에 잡는 법)

> **태스크 `result=0` + 로그 크기 무증가** 이면 → 로그 파일 잠금을 의심하라.

확인 명령:
```powershell
try { $fs=[IO.File]::Open($log,'Append','Write','None'); $fs.Close(); '쓰기가능' }
catch { $_.Exception.Message }
```

`being used by another process` 가 나오면 확정.

### 왜 직접 실행은 성공했나

리다이렉션 없이 stdout 으로 뽑았기 때문. **진단 실행이 성공한다고 태스크가 성공하는 게 아니다.**
둘의 차이(리다이렉션·권한·작업디렉터리)가 곧 원인일 수 있다.

## 세 번째 교훈 — `.cmd` LF 단독은 `if`/`set /a` 줄에서 실제로 터진다

아침 점검에서 LF 단독 줄을 발견하고도 **"경미"로 분류했다.** probe 테스트에서
`if`/`goto`/`set /a` 줄을 빼고 검증했기 때문이다. 그 빠진 줄이 정확히 범인이었다:

```
if %ERRORLEVEL% EQU 0 exit /b 0     ← LF 단독
```

증거는 로그에 있었다 — `S03_SIGNAL_RESTART 0/3`. `set /a` 가 안 먹어 카운터가 안 올랐다.
그리고 `'\python.exe' is not recognized` (경로가 잘림).

> **런처를 검증할 때 실행 줄·분기 줄을 빼면 검증이 아니다.** 빠진 줄이 범인이다.
