# 2026-07-26 C2-01 공통매도 연결에서 시세시각이 naive라 상태 계약이 거부된 문제

## 접근법
1. C2-01의 신선한 `BUY_READY`만 고르는 주문 없는 브리지를 만든다.
2. 새 주문 구현 대신 기존 `_open`·`BUY_PENDING`·부분체결·재시작 복구 경로로 연결한다.
3. 체결된 C2-01 포지션만 기존 공통 상승보유·매도 엔진으로 분기한다.
4. 실제 공통 손절 판정을 단위 테스트해 `timezone-aware datetime required` 오류를 재현한다.
5. 어댑터 경계에서 기존 KST 관측시각의 timezone을 진입시각에 붙인다.
6. 신규 9개, 배선 계약 13개, 기존 74개 검사를 다시 실행해 모두 통과시킨다.

## 하지 않은 것 + 이유
- 공통매도 계산식은 수정하지 않음. 이유: 오류 원인은 매도 규칙이 아니라 어댑터의 시각 계약 위반이었다.
- 새 주문 API나 재시도 로직은 만들지 않음. 이유: 기존 엔진의 주문번호 확인·중복 방지·부분체결·타임아웃 복구를 재사용하는 편이 더 안전하다.
- 실계좌 주문과 `captain2_off.flag` 제거는 하지 않음. 이유: 코드 검증과 실제 주문 권한을 분리해야 한다.

## 재사용 규칙
naive 거래소 시각을 timezone-aware 상태 엔진에 넘길 때는 어댑터 경계에서 거래소 timezone을 명시하고 실제 상태 판정 테스트를 실행하라.
