# [2026-08-12] 배치 조회 중 안전 잔고 조회 지연

## 문제 정의
브로커 게이트웨이가 종목 배치 조회를 처리하는 동안 매수 전 잔고 조회가 제한시간 안에 처리되지 않아, 정상 매수 신호가 `PREBUY_BALANCE_UNAVAILABLE`로 소멸했다.

## 접근법
1. 전략 3 상태와 로그에서 신호 생성 뒤 잔고 조회 제한시간 초과가 반복되는지 확인한다.
2. `StrategyBroker.prebuy_holdings()`와 브로커 요청 우선순위를 따라가며 요청 생성부터 실제 처리까지 추적한다.
3. 우선순위 큐에 안전 조회가 먼저 놓여도, 이미 시작된 `BATCH_TR` 내부 반복이 끝날 때까지 선점할 수 없음을 확인한다.
4. `BATCH_TR`의 종목 경계마다 실제 주문뿐 아니라 우선순위 1 안전 조회도 처리하도록 수정한다.
5. 안전 조회 선택 함수와 실패 폐쇄형 승인 해시 검사를 읽기 전용 검증으로 확인한다.
6. 실전 보유 포지션이 있으면 게이트웨이 재시작을 미루고, 모든 전략 포지션이 비었을 때만 수정 코드를 활성화한다.

## 하지 않은 것과 이유
- 잔고 조회 제한시간만 늘리지 않았다. 이유: 배치가 길어지면 같은 장애가 다시 발생하고 신호 지연만 커진다.
- 보유 종목이 있는 상태에서 즉시 브로커를 재시작하지 않았다. 이유: 매도 감시와 주문 경로를 잠시 끊을 수 있다.
- 승인에서 제외된 전략 2 재매수 경계 조건은 변경하지 않았다. 이유: 사용자 승인 범위를 넘는다.

## 재사용 규칙
우선순위 요청이 있더라도 긴 작업 내부에서 선점 지점이 없으면 우선순위는 보장되지 않는다. 긴 배치는 안전한 단위 경계마다 주문·잔고·상태 같은 안전 요청을 명시적으로 선점 처리하라.
