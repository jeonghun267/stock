# [2026-07-24] 캡틴2 코스닥 선별기 허용목록 연결

## 문제
캡틴2가 코스닥 돈맥 선별기 약 200종목이 아니라 시장 구분이 없는 `micro_rank_board.json` 전체 종목을 읽어, 코스피 `009540`까지 실제 매수했다.

## 접근법
1. 실행 CMD와 캡틴2 진입시간·세 레인(EARLY·RAID·PULL)의 공통 `_entry_filter()` 호출을 확인했다.
2. 오늘 이벤트 CSV에서 실제 매수 13건을 추출하고 EOD 시장구분 및 돈맥 선별기 `univ_codes`와 대조했다.
3. 캡틴2의 신호 입력은 837종목 `micro_rank_board.json`, 허용 유니버스는 별도 `돈흐름_선별판.json`임을 확인했다.
4. 기존 코스닥 선별기 `univ_codes`와 아침대장 `captain`을 5초 캐시로 읽어 세 레인 공통 신규진입 관문에 연결했다.
5. 선별판이 당일 자료가 아니거나 비어 있으면 신규매수만 차단하고 기존 보유 매도 관리는 계속하도록 했다.
6. 현재 선별판으로 `009540` 거부, `028300`·`0156T0` 허용, EARLY의 거래대금 우회에서도 동일 관문 적용을 검증했다.

## 하지 않은 것 + 이유
- 캡틴2가 돈맥 선별판을 직접 입력으로 쓴다고 가정하지 않았다. 실제 코드는 `micro_rank_board.json`을 입력으로 사용했다.
- 영문이 섞인 `0156T0`를 코드 모양만 보고 차단하지 않았다. 기존 키움 코스닥 선별기 `univ_codes`에 실제 포함되어 있었다.
- 공유 `micro_rank_board.json` 자체를 코스닥 200종목으로 축소하지 않았다. 다른 소비자에게 영향을 줄 수 있어 주문 소비자인 캡틴2에만 관문을 추가했다.
- 가격·100억 거래대금·역배열·손절·매도 조건은 변경하지 않았다.

## 재사용 규칙
신호 보드와 매매 허용 유니버스가 분리되어 있을 때는 신호 생성기를 추정으로 축소하지 말고, 주문 소비자의 공통 진입 관문에서 당일 허용목록을 재검증하라.
