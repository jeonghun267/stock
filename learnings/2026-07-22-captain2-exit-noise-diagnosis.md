# [2026-07-22] 캡틴2 첫날 승률 13%의 원인 규명 — 매도 규칙이 문턱 노이즈에 팔고 있었다

## 접근법
1. 로그에서 매도 30건 전부 추출해 사유·손익 집계 → 전부 단일 사유(FLOW_WEAK+STRUCTURE_BREAK), 다수가 임계(48%) 바로 아래 47.x%에서 매도됨을 확인
2. "조기매도" 가설을 검증하기 위해 키움 opt10080 분봉을 batch_tr 1회(23종목)로 직접 조회 → 매도 후 +15분에 76%가 매도가보다 위(평균 +0.41%) = 가설 확정
3. 코드에서 매도 3조건을 분해 → 구조붕괴가 "직전 5초 저가 하회"라 하락틱 1개에도 참, 확인시간 2초는 사실상 무의미함을 확인
4. 재생 로그(초단위)로 매도 직전 하락 지속시간 측정 → 4~19초 (표본 5건)
5. "매도조건 연속 15초 유지" 단일 수술 선택 — 지속 요구 하나가 문턱 노이즈와 헐거운 구조붕괴를 동시에 잡음
6. 경로 격리(env 오버라이드) 리허설 5케이스 통과 후 프로세스 재기동 → 실전 로그로 작동 확인

## 하지 않은 것 + 이유
- 매도 임계값(0.48) 하향이나 구조붕괴 여유폭(틱) 추가는 하지 않음. 이유: 한 번에 수정 1개 원칙 — 지속확인만으로 두 증상이 다 잡히는지 그림자에서 먼저 검증. 여러 축을 동시에 바꾸면 원인 추적 불가
- 재생 로그 기반 변형 4종 백테는 시도했으나 채택하지 않음. 이유: 재생 로그가 13:09 이후만 커버(그 전 재시작들 때문)해서 매도된 30건의 초단위 리플레이가 불가능 — 표본 없는 백테로 정밀 튜닝하는 척하지 않고, 분봉 실측(방향)+지속시간 분포(크기)로 근거를 잡음
- 누적비율 대신 윈도우 비율로 재설계하지 않음. 이유: "결함 수정" 범위를 넘는 전략 재설계 — 그림자 데이터가 쌓인 뒤 별도 판단

## 재사용 규칙
매도 규칙을 의심할 때는 "매도 후 N분 뒤 가격"을 실데이터로 먼저 재라 — 매도가보다 위인 비율이 높으면 신호가 아니라 노이즈에 팔고 있는 것이다.
