# 2026-08-25 S06이 정상적으로 원자 교체되는 실시간 스냅샷을 빈 파일로 오인해 신규 진입을 순간 차단했다

## 접근법
1. S06 전용 로그에서 `SNAPSHOT_EMPTY` 발생 횟수와 시각 분포를 집계했다.
2. `_snapshot()`의 두 번 읽기·동일성 검사와 브로커의 1초 원자 교체 쓰기 경로를 대조했다.
3. 경고가 상태 전환 때만 기록됨을 확인해 연속 장애와 개별 읽기 충돌을 구분했다.
4. 두 번 읽기 실패 시 직전 정상본의 상위 `ts`가 신선도 제한 안에 있을 때만 재사용하게 수정했다.
5. 비숫자 종목 필터와 신선/오래된 캐시의 허용·차단을 집중 시험하고 S06 승인 해시를 재봉인했다.

## 하지 않은 것 + 이유
- `SNAPSHOT_EMPTY` 경고만 숨기지는 않음. 이유: 실제 생산기 중단도 같은 증상이므로 관측 가능성을 남겨야 한다.
- 직전 정상본을 무기한 재사용하지 않음. 이유: 오래된 시세로 신규 주문 판단이 진행되는 것을 막아야 한다.

## 재사용 규칙
원자 교체 파일을 고빈도로 읽을 때는 정상 갱신 중 내용 차이를 손상으로 단정하지 말고, 마지막 정상본을 명시적 신선도 한도 안에서만 재사용하라.
