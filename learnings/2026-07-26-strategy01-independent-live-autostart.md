# 2026-07-26 모놀리식 구전략을 실행하지 않고 독립 전략을 월요일 자동시작 경로에 안전하게 연결

## 접근법
1. 기존 신호·공통 상승보유/매도·BrokerClient·체결 CSV·공용 슬롯·예약작업을 읽어 재사용 가능한 계약과 구전략 전용 코드를 분리했다.
2. 매수 판정, 신호 감시, 공통 상승보유/매도, 공통 주문 어댑터, 전략 실행 상태를 각각 새 파일로 만들고 구전략 import가 0인지 검색했다.
3. 실전 승인 파일과 OFF 파일을 이중 관문으로 두고, 승인 전에는 `S01_LIVE=YES`여도 주문 0 SHADOW가 되게 만들었다.
4. 발주 전에 하루 1회 시도와 멱등성 키를 저장하고, TIMEOUT·예외를 실패로 단정하지 않고 주문번호·미체결·체결 CSV·실계좌 잔고를 대조하게 만들었다.
5. 매수/매도 취소는 종목 전체 취소가 아니라 확인된 원주문번호만 사용하고, 잔고 진실을 확인할 수 없으면 재주문 대신 `RECOVERY_BLOCKED`로 멈추게 했다.
6. 사용자 권한 예약작업 두 개를 등록하고 `StartWhenAvailable`을 켰으며, 평일 08:15~09:19에만 선행 작업을 깨우는 보완기를 실행 명령에 연결했다.
7. 관리자 권한이 필요한 구전략 예약 비활성화는 UAC를 요청하는 사용자 승인 버튼으로 분리하고, 권한이 없어도 구전략 OFF가 유지되게 했다.
8. 독립 단위검증 7건, 공통 회귀검증 66건, 전체 회귀검증 140건, 실제 예약작업 주문 0 시동을 순서대로 실행했다.
9. 전체 테스트가 새 공용 감시파일을 오염시키는 부작용을 해시 비교로 발견해 임시경로로 격리하고 100종목 목록을 복구했다.

## 하지 않은 것 + 이유
- 실계좌 승인 파일 생성과 OFF 해제는 하지 않음. 이유: 실계좌 활성화는 사용자가 경고를 읽고 `실전승인`을 직접 입력해야 하는 최종 권한 변경이다.
- 기존 구전략 파일을 삭제하지 않음. 이유: 예약 XML과 OFF 상태를 보존해야 롤백과 사후 비교가 가능하다.
- 공통 상승보유·매도 임계값을 바꾸지 않음. 이유: 이번 범위는 독립 실행과 안전 배선이며 매도 공식 변경은 별도 사용자 승인이 필요한 동작 변경이다.
- TIMEOUT 뒤 즉시 재주문하지 않음. 이유: 응답 누락 상태에서 재주문하면 중복 체결이 발생할 수 있어 브로커 진실 대조가 먼저다.

## 재사용 규칙
모놀리식 실전 전략을 독립 프로세스로 이식할 때는 신호·상태·주문번호·승인·예약작업을 독립 소유하게 하고, 브로커 진실을 확인할 수 없을 때는 재주문하지 말고 복구 차단하라.
