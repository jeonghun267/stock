# [2026-07-20] 캡틴이 매수 3초 만에 자동 매도 — 원인은 "매수는 이평선을 안 보는데 매도는 10일선 아래 무조건"인 자기모순

## 접근법
1. 체결 CSV(fills)로 실제 왕복 9건의 매수가·매도가·보유시간을 확정 (엔진 로그 %는 주문시점가 기준이라 신뢰하지 않음)
2. 엔진 로그에서 각 매도의 발동 사유 문자열을 수집 ("10일선붕괴(보험)" 3건 · "꼭지매도(classic)" 6건)
3. 엔진 코드에서 매도 체인의 정확한 우선순위와 조건을 읽음 — ⑤10일선은 고점·체결강도 조건 없이 `cur < MA10D`면 무조건 발동(672행), 진입 로직(506~522행)엔 이평선 검사가 아예 없음을 확인
4. 엔진이 실제로 쓰는 바로 그 일봉 파일(eod_daily_bars.csv)과 동일한 계산식(_ma_daily: 최근 10개 종가 평균)으로 9종목의 10일선을 재현해 진입가와 대조 → 3초 매도 2건(코오롱티슈진 -24.2%·제주반도체 -2.8%)은 매수 순간부터 조건 충족(태생적 즉사), 트레일 매도(피에스케이·테크윙)는 진입 후 시장 하락으로 판정 분리
5. 승인 후 매도 ⑤와 정확히 동일한 조건을 매수 직전에 재사용하는 관문만 배선 (거부 로그 종목당 1회·검사는 매 루프·슬롯 소비 전 차단) → 컴파일 + 오늘 9건 리플레이로 "거부 2건 = 정확히 그 2건, 나머지 7건 통과" 검증

## 하지 않은 것 + 이유
- "2~3틱 안에 발동할 위치" 예측 조항은 구현하지 않음. 이유: 지시서 스스로 "새 계산식 금지"라 했는데 틱 예측은 새 계산식+매직넘버이고, 의미 있게 만들려면 여유폭 파라미터(전략 변경)가 되므로 백테 없이 넣으면 안 됨. 주성엔지니어링(10일선 +0.4% 경계 진입, 19초 사망)을 못 막는 건 알려진 한계로 명시하고 데이터 검증 뒤로 미룸
- 트레일(-0.5%)·손절·슬롯 등 다른 규칙은 손대지 않음. 이유: 짧은 보유시간의 나머지 원인은 급락장 변동성 × 트레일의 정상 작동이라 "버그"가 아니고, 246일 백테로 확정된 파라미터라 장중 감으로 못 건드림
- 새 프로그램·새 파일을 만들지 않음. 이유: MA10D는 엔진 기동 시 이미 항상 계산되므로(441행) 검사 한 블록 삽입이면 충분
