# [2026-08-12] 종가 조회 지연과 비동기 예약 작업의 거짓 성공

## 문제 정의
15:18 종가매수의 `opt10032`가 장시간 `opt10059` 수집 뒤에서 대기해 호출자는 시간 초과했고, 그림자 예약 작업은 자식 프로세스가 실패해도 비동기 실행기가 즉시 성공으로 끝나 실제 실패가 숨겨졌다.

## 접근법
1. 종가매수 로그와 브로커 저널의 요청·응답 시각을 대조해 `opt10032` 응답이 호출자 제한시간 뒤에 도착했음을 확인한다.
2. 같은 시각 실행 중인 예약 작업과 프로세스를 역추적해 장시간 `opt10059` 수집기를 찾는다.
3. 주문·잔고 우선순위를 유지하면서 `EODGAP_` 조회와 실시간 등록만 일반 TR보다 앞에 배치한다.
4. 14:58~15:20에는 비필수 수급 조회를 멈추고, 주문 없는 사전조회로 당일 자료를 저장한다.
5. 그림자 등록은 재시도하고 실패 시 세션 JSON을 남기며, 전용 대기 실행기는 자식 종료코드를 반환하게 한다.
6. 생산 브로커를 재시작한 뒤 주문 없는 생산 진입점으로 `opt10032` 조회와 예약 작업 종료값을 확인한다.

## 하지 않은 것 + 이유
- 전날 거래대금 보드를 대체 자료로 사용하지 않았다. 이유: 당일 종가 후보가 바뀌어 잘못된 실제 매수로 이어질 수 있다.
- 저장된 2분 캐시를 바로 실제 후보 선택에 사용하지 않았다. 이유: 현재 생산 경로의 재현 검증이 끝나기 전에는 라이브 자료 대체를 활성화할 수 없다.
- 공용 비동기 VBS를 전역 수정하지 않았다. 이유: 여러 예약 작업의 실행 방식이 함께 바뀌는 승인 범위 밖 변경이다.

## 재사용 규칙
시간 제한이 있는 핵심 조회를 보호할 때는 호출자 제한시간만 늘리지 말고, 생산자 큐의 우선순위·경쟁 작업의 시간대·예약 작업의 실제 종료코드를 함께 검증하라.
