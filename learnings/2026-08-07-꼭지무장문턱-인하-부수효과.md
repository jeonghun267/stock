# [2026-08-07 밤] 문턱 하나(꼭지무장 4→2)를 내렸더니 이웃 분기가 산수상 죽은 코드가 됐다

## 접근법
1. 합의된 값 변경(코드+계약서 동시)을 먼저 하고 전체 시험을 돌렸다
2. 새 실패 3건이 전부 "꼭지 +4% 미만 = 방어영역" 전제의 시험임을 실패 메시지로 확인했다
   (기준선 11건과 이름 대조 — 8/5 "A/B는 실패 메시지까지" 규칙)
3. 코드를 읽고 이유를 찾았다: 이익방어 분기 조건이 `꼭지수익 < 무장(2.0) AND 현재수익 >= 2%`인데
   꼭지수익 >= 현재수익이 항상 참이라 **이 분기는 이제 어떤 입력으로도 참이 될 수 없다**
4. 낡은 시험 3건을 새 문턱 기준으로 교체하되, 죽은 분기 사실을 시험 주석·계약서·memory.md 에 남겼다

## 하지 않은 것 + 이유
- **죽은 분기를 지우지 않음.** 이유: 합의는 "꼭지무장 하나만"이고, 그 구간(+2~4%)을 꼭지매도가
  더 빠른 조건으로 덮으므로 보호 공백이 아니다. 삭제는 별도 승인 후.
- **이익방어의 수익 문턱(2%)을 같이 내리지 않음.** 이유: "한 번에 하나만"(I항) — 동시 수정은
  효과 추적을 불가능하게 한다.

## 재사용 규칙
경계값(문턱)을 바꿀 때는 그 값과 부등호로 얽힌 **이웃 분기들의 도달 가능성**을 함께 검산하라 —
"A < 문턱 AND B >= 상수" 꼴은 문턱이 상수 밑으로 내려오는 순간 죽는다.
